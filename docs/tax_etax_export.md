# XTX（e-Tax 申告データ）出力 設計と検証計画

状態: **Phase 0 の調査と計画。実装は Phase 7。公式ソフトでの取込試験が完了するまで利用者に公開しない。**
2026-11-11 時点の公式資料に基づく。

---

## 1. 結論（利用経路）

| 経路 | 可否 | 根拠 |
|---|---|---|
| 確定申告書等作成コーナーに NOXIA の .xtx を取り込む | **不可**。作成コーナーが読み込めるのは自身の .data のみ。民間ソフトの決算書データの組み込みもサポート外 | https://www.keisan.nta.go.jp/r7yokuaru/cat1/cat15/cid363.html 、 https://www.e-tax.nta.go.jp/toiawase/faq/sousin/03_1.pdf 、 https://www.keisan.nta.go.jp/r7yokuaru/cat1/cat16/cat163/cid1128.html |
| **e-Tax ソフト（WEB 版）** で .xtx を読み込んで送信 | 可（読み込み→帳票選択→電子署名→送信。編集は不可） | https://www.e-tax.nta.go.jp/toiawase/qa/e-taxweb/49.htm （更新 令和8年10月22日） |
| **e-Tax ソフト（ダウンロード版）** に .xtx を「組み込み」 | 可（帳票の表示・編集・署名・送信） | https://www.e-tax.nta.go.jp/toiawase/qa/yokuaru05/10.htm |
| NOXIA から e-Tax へ直接送信 | **実装しない**（仕様 §0）。API も「エンドユーザが利用者識別番号を取得しログインしていることが前提」で、送信は API 対象外 | https://www.e-tax.nta.go.jp/shiyo/api.htm |

したがって XTX は「作成コーナーを使わず、e-Tax ソフトで申告する利用者」向けの上級機能。主経路は入力ガイド（`tax_etax_input_guide.md`）。利用者には利用者識別番号と電子署名（マイナンバーカード等）が必要であることを案内する。

## 3. 対象帳票（令和8年分）

| 帳票 | 様式の状況 | 備考 |
|---|---|---|
| 所得税及び復興特別所得税の確定申告書 第一表・第二表 | 令和8年分（案）公表済み（令和八年分以降用、控用廃止、⑳基礎控除・特定親族特別控除欄） | 帳票 ID と XML は確定版で確認 |
| 収支内訳書（一般用） | 現行「令和5年分以降用」。令和8年分の改訂は未公表 | 1・2 ページ目 |
| 所得税青色申告決算書（一般用） | 同上 | 1〜3 ページ目（10 万円控除は B/S 不要。B/S を出すかは要確認） |
| 第三表・第四表・住宅ローン・医療費明細など | 対象外（未対応の所得・控除） | 該当者は出力不可 |

## 4. 実装計画（Phase 7）

| 段 | 作業 | 成果 |
|---|---|---|
| 1 | 確定版仕様（11/25 以降）を取得し、`docs/etax_spec/README.md` に版・取得日・ファイルの sha256 を記録（仕様書本体はリポジトリに入れず、保管場所を記す） | 版管理 |
| 2 | 帳票 ID・フィールド対応表 `apps/tax/data/xtx/R8/fields_*.json`（NOXIA の computed キー → XML 要素パス、型、桁数、必須） | 対応表（人が仕様書と照合） |
| 3 | 生成 `apps/tax/exports/xtx.py`（lxml、文字コード・改行・数値表現は仕様書どおり。金額は整数文字列） | .xtx |
| 4 | **XSD 検証**（項番 19）。失敗は `TaxExport.validation.schema=failed` で保存し、出力不可 | 自動 |
| 5 | **帳票間連動の検証**（項番 8）: 決算書の所得金額＝申告書の事業所得、収支内訳書の売上＝申告書の収入など | 自動 |
| 6 | **必須項目の検証**: 未入力があれば生成せず一覧を返す（ミセミル `filing/csvfile.py` の「足りなければ何も出さない」方針） | 自動 |
| 7 | **公式ソフトでの取込試験**（手動・運営者）: e-Tax ソフト（ダウンロード版）に組み込み→全帳票の表示→金額・項目の一致確認、WEB 版での読込確認。テストデータは架空の事業者（利用者識別番号はテスト用の取得方法を e-Tax 問い合わせで確認） | 試験記録（§6） |
| 8 | 運営者レビュー → `TaxYearConfiguration.forms.xtx.verified=true` → `TaxExport.is_released` の既定を true に（年度ごと） | 公開 |
| 9 | 以後、仕様の更新（第 4 回公開・正誤）を追跡し、差分があれば 2〜7 を再実施 | 保守 |

実装規則:
- XTX の生成は `TaxReturnVersion`（凍結された計算結果）からのみ。`TaxReturn` の現在値から直接作らない。
- 生成物の sha256・使った仕様版・検証結果を `TaxExport` に保存。ダウンロードは `TaxAuditLog`。
- 検証未完了の年度では、画面に XTX のボタンを出さない（運営者のみ `GET /api/tax/exports` で取得可）。
- 利用者向けの文言: 「e-Tax ソフト（WEB 版／ダウンロード版）で読み込んで送信するためのデータです。確定申告書等作成コーナーには取り込めません。送信には利用者識別番号と電子署名が必要です」。
- **CSV を所得税申告書として取り込めるとは案内しない**（作成コーナーも e-Tax ソフトも CSV 取込は法定調書等の別手続）。

## 7. リスク

| リスク | 対策 |
|---|---|
| 仕様の確定版が遅れる・第 4 回公開で変わる | 対応表をデータ化し差分で追う。検証が済むまで非公開 |
| 作成コーナー利用者が XTX を使おうとして混乱 | 画面と手引きで経路を明記。ガイド（転記）を主経路に |
| e-Tax ソフト側の表示が仕様書と異なる | 公式ソフトでの取込試験を必須にし、記録を残す |
| 利用者識別番号・電子署名の準備不足 | ガイド第3部で事前準備を案内 |
| 誤ったデータの送信 | 版の凍結・検証・監査ログ。送信は本人が e-Tax ソフトで行い、NOXIA は送信しない |
