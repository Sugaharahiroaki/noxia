# NOXIA 店舗タブレットPOS｜Claude Code 実装プロンプト

NOXIAの既存リポジトリで、以下の映像分析を仕様の参照元として、横向きiPadの店舗スタッフ用POSを実装してください。対象は店舗タブレットと、その操作に必要な既存API・業務処理です。別途確認予定のオーナー用PC管理画面のデザインや業務は今回の対象外です。この文書単体で作業できます。

## 1. 既存実装の確認

最初に店舗POSの入口、ルーティング、店舗切替と権限、卓・伝票・顧客・セット・注文・バック・会計のモデル、金額計算、既存テストを確認してください。想定構成はNext.js＋Djangoですが実物を優先します。下の各操作を「既存を再利用」「UIを接続」「不足機能を実装」「映像では仕様未確定」に対応付け、短い実装方針を示してから、接続可能な範囲を実装・検証してください。既存のタブレット入口から開けるようにし、見本データだけの独立ページで終えないでください。

## 2. 現場の操作順と画面のつながり（元動画 IMG_8729.mp4、時刻は目安）

## 3. UIの再現指示

- iPad横向き、特にiPad miniでホールと注文を実用可能にする。縦長で撮った動画の中に横長タブレットが映っている。動画全体の縦横比を画面仕様に使わない。
- 上端は横一列の営業ヘッダー。左からメニュー、未精算・精算済・売上合計、日付時刻、ホール状況、注文、待機キャスト、設定、トップ。主要機能は丸いアイコン＋日本語ラベル、状態数は赤バッジ。モーダルや集中入力画面では戻り先の卓を保持する。
- クリーム系の面、金～黄土色の見出し帯、細い区切り、選択行は濃い背景。空席は青系、使用中は黄～金、確定・延長は青系、＋は橙、－は赤。文字で状態を併記する。NOXIA名と既存アイコンを使用。写真に写る反射や模様まで再現する必要はない。
- ホールは横5列を目安に卓カードを格子配置。カウンター・BOX・出前・店内フードなど設定された営業枠を順に表示。空席は卓名と大きな「空席」。使用中は卓名、タグ、人数、残分、開始～終了、金額。時間超過はマイナスと警告印。通常タップ＝開く、長押し＝操作メニュー。長押し後に通常タップも発火しないようにする。
- 卓詳細は上段に卓名、タグ、人数の増減、出戻り。左列はセットの時系列と各行の時間帯・単価・人数・編集。右列は延長候補ごとの金額、対象客、編集・延長・自動。下端に現金／カードの金額と明細・注文・会計等の操作を集める。延長候補の見込み金額と現在の伝票額を区別する。
- 注文の列順は「カテゴリー｜メニューと単価｜誰に付けるか｜今回の注文」。担当が異なる同一商品は別行とし、右列の＋／－で数量調整。折半は注文画面に重ねるパネル。元の卓、カテゴリー、商品、入力途中の明細を保つ。
- 設定は「左の設定項目｜中央の一覧・検索・追加・編集｜右の詳細」。単一設定は中央＋右を広いフォームとして使う。リストのみ独立スクロール。タップ領域は目安44px以上、ソフトキーボード表示時も決定や入力中の値へ到達できること。

## 4. 設定値と営業画面の対応

| タブレットで見えた設定 | 営業時の利用先・実装上の扱い |
|---|---|
| テーブル名・表示・背景色、セット構成の名称・詳細・表示・コピー | ホールの卓カード、空席選択後のセット候補。同じ店舗マスターを参照 |
| カテゴリー、商品名・略称・注文用カテゴリー、キープ・在庫ありの表示 | 注文のカテゴリー／商品列。キープや在庫引落の詳細は既存仕様を確認 |
| タグ名・色・ホール表示、お客様情報 | 卓のタグ選択、カードの表示。顧客属性と伝票タグの既存の違いを維持 |
| セット時間、セット料金、呼び料金、料金、同伴料金、注文オプション | 入店の候補、延長・注文・同伴等の計算元。時間0の意味や無制限の扱いは既存定義を確認 |
| 各種調整（卓作成時の時間、会計アラート、バック表示、勤怠／オーダーストップの丸め、キャスト折半時の小計） | 店舗設定を参照。動画の「10分前」等を全店共通値にしない。NOXIAの既存アラーム設定と接続 |
| 料金計算設定（税サ・合計・C利用料・内消費税の丸め、総額表示制御） | 卓詳細、明細、会計で同じ計算結果を使用。「C利用料」は映像のラベル。既存項目との対応が確認できてから接続 |
| プリンター、制御設定、名称変更 | 概算伝票・会計伝票・精算伝票・領収書、キッチン印刷、注文チャイム、卓表示デザイン、ラベルのカスタムと初期値復元 |
| レシート設定、領収書設定 | 店名・住所・電話・ロゴ、登録・テスト印刷、内消費税額表示、日付の営業日／暦日。実機未接続の場合は印刷成功と表示しない |

マスター変更後は次の新規伝票・注文に反映し、既存確定明細の単価やバックを遡って書き換えない。タブレット設定の編集権限はNOXIAの店舗ロールに従う。

## 5. 伝票と集計の実装条件

- 営業中の卓・人数・セット・注文・各キャストへの配分・支払いは同じ伝票IDに結び付ける。卓を移した場合も既存仕様に沿って明細を追跡できること。ホール、卓詳細、明細、会計のどこで更新しても同一の金額を表示する。
- 入店ウィザードと注文作成中は下書き。戻る／キャンセルで売上を増やさない。注文確定は一度だけ反映。販売額とバックは別項目にし、担当者数で販売額を重複計上しない。例の不均等配分を扱い、上限・端数は既存設定に合わせる。
- 仮会計・会計入力を開いた段階は未精算。会計確定時だけ既存の支払処理で精算する。会計画面にカード欄があることから決済端末連携を推定しない。
- 営業中伝票の削除は卓名を表示して確認し、未精算表示から除いて空席に戻し、取消履歴を保存。確定売上の取消や返金は既存の別処理に従う。会計・注文・延長・取消は二重タップや通信再試行で重複しないこと。異なる店舗の卓・キャストを操作できないこと。
- 営業日をまたぐセット（例23:20～00:20）を扱う。時間は終了日時から再計算し、画面再表示・スリープ復帰で残分と警告を復元。自動延長と料金発生のタイミングは既存仕様に従う。

## 6. 動画と照合する受入シナリオ

1. 空席BOX3を選び、2名・60分・単価3,500円で開始。卓詳細に3,500円×2、ホールに2名、終了時刻、未精算額が出る。タグ「呼び」を付けてホールでも確認。
2. 1名追加して3名、対象を指定して退店し2名へ。30分延長で2セット目が追加され、取り消すと元のセットと金額に戻る。既存注文や他卓は変化しない。
3. 1,000円のドリンクを担当別に1・1・4杯確定。シャンパンの折半を200円／3,800円で編集して数量0で終了。伝票にドリンク6杯のみ。小計は7,000＋6,000＝13,000円。動画の会計額15,600円との差2,600円は「サービス料＋税」の画面例。内訳や固定税率は推定しない。同じ設定を用意できない場合は既存の料金設定による再計算値で検証。
4. 映像では既存の他卓合計29,400円 → BOX3開始時37,800円 → 注文後45,000円。会計プレビューを閉じてもBOX3は使用中。伝票操作で削除をキャンセルすれば維持。削除を確定すると空席となり合計29,400円、取消履歴が残る。この数値を本番に埋め込まない。
5. 実装後は既存テスト・型チェック等を実行し、可能な環境でiPad mini相当の横画面を操作。空席→入店→注文→明細→会計入力→戻る→取消を通して確認する。報告には変更ファイル、各画面の入口、確認結果、実機検証待ち、未確定ルールを記載する。
