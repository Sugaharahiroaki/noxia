# NOXIA 統合計画（タブレット POS ＋ 管理用集計）

作成日: 2026-11-17 ／ 対象コミット: `f0150b3`（`main`）

2 つの参照仕様を、既存の NOXIA に **1 つのアプリとして** 取り込むための計画。

- `spec/tablet_pos_video_spec.md` … 店舗タブレット POS（操作映像の分析）
- `spec/admin_reference_design.md` … 管理用 PC 画面（参考アプリの画面分析）

この 2 つは同じ参考アプリの表（タブレット）と裏（管理画面）で、タブレットで作った伝票を管理画面が集計する関係にある。NOXIA にはタブレット POS も管理・経理もすでにあるので、**新規アプリは作らず、足りない部分だけを NOXIA に足す**。

印の意味: ✅ 既存をそのまま使う ／ 🔌 既存 API に画面をつなぐ・画面を直す ／ 🆕 新しく作る ／ ❓ 仕様が決まっていない（6 章）

---

## 1. 統合の方針

| 項目 | 決めたこと | 理由 |
|---|---|---|
| アプリの数 | NOXIA 1 つ。同じ URL・同じ DB・同じログイン | 伝票を二重に持たないため |
| 技術 | NOXIA の現状のまま（Django + DRF / Next.js + Tailwind）。参考設計の Django テンプレート・Bootstrap・HTMX・pytest・WeasyPrint・Chart.js 前提は採らない | 既存 POS・経理が動いており、テストが 200 件以上ある |
| タブレットと PC の出し分け | ロールは増やさない。同じ画面を権限（ケイパビリティ）で出し分け、POS 画面は iPad 横向きに合わせる | NOXIA は「店舗ごとに 1 アカウントでログインしたまま」の運用で、権限は API で検証済み |
| 見た目 | POS 画面（ホール・卓・注文・会計・POS 設定）だけ、映像に合わせたクリーム＋金のテーマにする。管理・経理画面は NOXIA の今の見た目のまま。参考設計の緑ヘッダー・M PLUS 1p は採らない | 参考アプリの見た目をコピーしないため。経理画面への影響を避けるため |
| モデル名 | 既存の名前を使う（`CLAUDE.md` の対応表）。`Bill`・`Cast`・`Shop` などは作らない | 同じものを二重に作らないため |
| 主キー | 既存どおり連番。UUID にしない | 既存データ・URL・テストを壊さないため |
| 源泉徴収 | 既存機能を残し、`StoreSettings.withholding_enabled` で店舗ごとに切り替える。新しい集計画面は、オフの店舗では源泉の列を出さない | 参考設計は「作らない」だが、NOXIA には実装済みで使う店舗もある |
| サービス料率（現金 15%・カード 20%） | **今は実装しない**。オーナーの確認後に S1 フェーズで入れる（6 章 Q1） | タブレット仕様が「内訳や固定税率は推定しない」としており、併用・売掛時の扱いも不明 |
| 集計の置き場所 | 読み取り専用の集計は `apps/analytics` に足す。画面は `/reports/...` | 既存の `analytics/daily`・`monthly`・`breakdown` の延長 |

### 受入シナリオ（映像仕様 6 章。テスト用データで再現する）
テスト用の店舗に、60 分 3,500 円（1 人単位）のセット・30 分の延長候補・1,000 円のキャストドリンク・タグ「呼び」を用意する。金額は本番コードに埋め込まない。

1. 空席の卓で 2 名・60 分を開始 → 卓詳細に 3,500 円 × 2、ホールに 2 名・終了時刻・未精算額。タグ「呼び」を付けるとホールにも出る。
2. 1 名追加で 3 名 → 1 人を選んで退店し 2 名。30 分延長で 2 セット目が出る → 取り消すと元に戻る。注文と他の卓は変わらない。
3. 1,000 円のドリンクを担当別に 1・1・4 杯で確定。シャンパンは折半を 200 円／3,800 円に編集したあと数量 0 で終える → 伝票にはドリンク 6 杯だけ。小計は 7,000 ＋ 6,000 ＝ 13,000 円。合計はテスト用店舗の料金設定による再計算値で確かめる（15,600 円を期待値にしない）。
4. 会計入力を開いて閉じても卓は使用中。長押し → 削除をキャンセルすれば残る。削除を確定すると空席に戻り、ヘッダーの合計が開始前の値に戻り、取消履歴が残る。
