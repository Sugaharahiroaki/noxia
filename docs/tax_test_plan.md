# 会計・確定申告統合 テスト計画

状態: **Phase 0 の提案**。2026-11-11 作成。実装フェーズごとにテストを追加し、各フェーズ終了時に「追加件数・全件成功」を報告する。
既存: バックエンド 267 件（`PYTHONUTF8=1 .venv\Scripts\python.exe manage.py test apps`、PostgreSQL 上に `test_yorumiru`）、E2E は `.local/e2e/*.mjs`（Playwright、検証 DB `yorumiru_verify`、Django 8001 / Next 3001）。

---

## 1. 方針

1. **既存 267 件は常に全件成功**（POS・現金・日払い・源泉の回帰）。
2. 金額の計算は **一次資料の設例をゴールデンテスト**にする（国税庁の計算例・手引きの設例）。ミセミル `seed.verify_year_end_golden` の型（本番でも `--verify` で自己チェック）を採用。
3. 税制の値はテストにも直書きせず、`TaxYearConfiguration` の JSON を読んで検証する（JSON の値そのものは「出典・確認日」を持ち、公式資料と照合したレビューを別に行う）。
4. 二重計上の防止は「元データ→仕訳→帳簿→決算→申告」の **一貫性テスト**（売上合計＝仕訳の売上＝売上帳＝収支内訳書の売上）で担保する。
5. 権限は新 API ごとに **否定テスト**（他テナント・他店舗・他事業者・越権・運営者の税務判断不可）を必須にする。
6. 出力ファイルは **バイト列の再現性**（同じ版から同じ sha256）と **金額一致**（画面の計算値＝PDF/CSV/XLSX/XTX の値）を検証する。
7. E2E は iPad 横向き（1180×820）と PC（1366×768）の両方。既存どおり `seed_dev --reset` から始める。

## 2. 会計（Phase 1）

| ケース | テスト | 期待 |
|---|---|---|
| 現金売上 | 会計→締め→`journals.build` | 日次仕訳: 現金／売上（税率別）。JournalLine の貸借一致。売上帳＝Checkout 合計 |
| カード売上 | カード会計→締め | 売掛金（カード）／売上。売掛帳に未入金残高 |
| 決済手数料・入金消込 | CardSettlement（10,000・300・9,700） | 預金 9,700＋支払手数料 300／売掛金 10,000。売掛帳の残高 0。手数料の税区分は設定値（既定「非課税」要確認） |
| 返金・取消（同日） | 現金会計→取消 | 理論現金 0（**既存バグ修正後**）。仕訳は売上と返金が同日で相殺 |
| 返金・取消（別日） | 翌日に取消 | 元の日は売上、取消日に返金。ダッシュボードとの差を照合画面が説明 |
| 売上二重計上防止 | 同じ期間で `build` を 3 回、締め後に再開→締め | Journal 件数不変、revision のみ増える。再開した日の古い仕訳が stale 警告 |
| 現金経費（領収書あり／なし） | CashMovement(expense) に account あり／なし | 科目／現金 と 雑費／現金＋警告。Expense を別に作らない |
| スタッフ日払い | 既存 13 件＋仕訳行の確認 | 支払報酬料／現金・預り金・雑収入。スタッフ支払台帳に 1 行 |
| 事業主貸借 | 投入・引出 | 売上・経費に入らない。P/L 不変 |
| 手入力仕訳 | 貸借不一致 | 400。一致なら entry_kind=manual |
| 年度ロック | closed 年度に仕訳作成・取消・build | 拒否。再開→可能→イベント記録 |
| 帳簿ビュー | 現金出納帳の残高＝BusinessDay の理論現金推移、預金出納帳の残高＝銀行明細の残高 | 一致（差があれば差額行） |
| 科目 seed | 新 TaxPayer 作成 | 標準科目が作られ、`journals.ACCOUNTS` の全キーに対応する Account がある |
| 暗号化 | freee トークンの保存・読み出し・鍵ローテーション・鍵なし起動 | 復号一致、V2 で再暗号化、本番で鍵なしは起動失敗 |

## 3. 領収書（Phase 2）

| ケース | 期待 |
|---|---|
| AI 読取成功（mock） | `ocr_status=done`、値がスタッフ確認欄に入る、科目は提案のみ |
| AI 読取失敗・スキップ | `failed/skipped`、手入力で登録可。再試行で done |
| AI 無効（会社設定 off） | 呼び出さない。`skipped` |
| 予算超過 | 呼び出さない。`skipped`＋理由 |
| 内訳合計≠合計 | 警告つきで登録可。承認時に表示 |
| 複数レシート | `multiple_receipts` 警告、登録を止める |
| 手入力 | 必須項目チェック、未来日不可 |
| 重複（同一ファイル／類似画像／同取引） | 候補が付く。override 理由なしの承認は 409 |
| 既存レジ出金との結合 | 承認で既存 CashMovement に紐付く。新規作成しない |
| 承認（店舗現金・営業中） | CashMovement 作成、締めの理論現金が減る、日次仕訳に科目 |
| 承認（店舗現金・締め済み） | 409 で選択を要求。「締め後の修正」経路で ClosingRevision |
| 承認（個人資金／振込／カード） | Expense（paid_from 対応）／Payable。仕訳の相手科目が正しい |
| 差戻し→再提出→承認、却下、訂正 | 状態遷移と Event の記録。訂正は取消＋新規（corrected_from） |
| 原本閲覧権限 | スタッフは自分の店舗の自分の登録のみ。他店舗は 404。inline 配信に nosniff |
| スタッフ向け応答 | 科目・税区分・承認メモ・重複詳細が含まれない（シリアライザのテスト） |
| Idempotency | 同じキーで 2 回 POST → 1 件。処理中は 409 |
| 不正ファイル | 拡張子偽装（exe→jpg）、巨大画像、壊れた PDF、11MB → 400 |
| レジ出金突合 | 店舗×日の差分一覧（領収書なし・出金なし・金額差） |
| 電帳法項目 | origin・captured_at・検索（日付・金額・取引先の組合せ）・論理削除の履歴 |

## 4. 銀行（Phase 3）

| ケース | 期待 |
|---|---|
| CSV 取込（cp932・UTF-8 BOM・UTF-8） | 文字コード判定が正しい。見出し行の自動検出 |
| 列対応の推測と保存 | 初回は推測→確認→プロファイル保存。2 回目は自動適用 |
| 日付・金額の正規化 | 和暦・`YYYY年M月D日`・カンマ・全角・△ |
| 重複取込 | 同じファイル → 拒否。重なる期間の別ファイル → 行単位で重複をスキップし件数を報告 |
| 残高の連続性 | 前回最終残高と不一致 → `balance_check=mismatch` と警告 |
| 入金・出金の分類 | amount_in / amount_out の排他 |
| カード売上との照合 | 入金額＝期間のカード売上−手数料 → 候補（fee_diff）。確定で CardSettlement と手数料仕訳 |
| 経費支払との照合 | 金額一致・日付窓・名寄せ |
| 合算入金 | 2〜4 件の合計一致 → 候補。確定で配分 |
| 未照合一覧・対象外・振替 | 状態遷移と件数 |
| 手動消込・消込解除 | 解除で仕訳・CardSettlement が取消、明細が unmatched に戻る |
| 金額不一致 | 候補なし。手動で差額を手数料／雑損に振る操作 |
| 不正 CSV | 5,000 行超、バイナリ、数式セル → 400 |

## 11. 性能

- 銀行 CSV 5,000 行の取込 10 秒以内、照合候補の計算 5 秒以内（店舗 2・1 年分）。
- 元帳クエリ（JournalLine 年間 10 万行）1 秒以内（インデックス `(taxpayer, account, date)`）。
- AI 読取待ちはポーリング 2 秒、ジョブ 1 件 30 秒以内（超えたら failed→再試行）。
